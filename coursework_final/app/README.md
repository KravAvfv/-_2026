# Прототип АРМ «Щит-Лінк» — курсова робота з ПІС

Кравченко П., гр. ІР-31. Веб-застосунок (Python 3, Flask) поверх бази даних PostgreSQL 18: схема `db/schema.sql`,
функції, тригери, представлення, ролі й журнал аудиту з геш-ланцюгом `db/impl.sql`, тестові дані `db/seed.py`.
Організація РЦПДО «Щит-Північ» і всі дані вигадані.

## Запуск

Потрібні Python 3.11+ і PostgreSQL 18 (сервер, утиліти `initdb` і `pg_ctl` мають бути в `PATH`).
Перевірено на Linux.

```sh
git clone -b coursework --depth 1 https://github.com/KravAvfv/-_2026.git shchit && cd shchit
python3 -m venv .venv
.venv/bin/pip install -r coursework_final/app/requirements.txt
.venv/bin/python coursework_final/app/serve.py
```

Відкрийте http://127.0.0.1:5080. Скрипт сам створює тимчасову базу даних, заповнює її тестовими даними й запускає
застосунок; Ctrl+C зупиняє його і видаляє базу (кожен запуск — знову чисті дані). Інший порт:
`PORT=5090 .venv/bin/python coursework_final/app/serve.py`.

Типово завантажується розширений демонстраційний набір: історія за 4 місяці (≈ 134 місії в усіх станах),
12 «живих» треків, ≈ 300 перехоплювачів і 72 сенсори в усіх станах, 64 облікові записи. Ключ `--basic` запускає
менший набір, на якому зроблено знімки екрана й числові факти пояснювальної записки.

Пароль усіх облікових записів — `shchit-demo`.

| Логін | Роль |
|---|---|
| `och1` | оперативний черговий |
| `obu1` | офіцер бойового управління |
| `an1` | аналітик |
| `cmd01`, `cmd02`, … | командири розрахунків |
| `pilot01`, … | оператори |
| `r06_1` | пост спостереження |
| `r07_1` | технік |
| `r08_1` | логіст |
| `r09_1` | аналітик ефективності |
| `r10_1` | адміністратор |
| `r11_1` | офіцер кібербезпеки |
| `r12_1` | начальник центру |
| `r13_1` | інструктор |

## Сценарій демонстрації

| Крок | Хто | Що показати |
|---|---|---|
| 1 | `och1` | Головна: «Очікують санкції (2)» → відкрити місію → «Санкціонувати» (правило двох осіб: пропонує ОБУ, санкціонує ОЧ) |
| 2 | `och1` | «Обстановка»: мнемосхема, черга загроз за рівнем загрози й часом підльоту |
| 3 | `an1` | Трек у стані «підтверджений», належність «невідома» → класифікувати як ворожу |
| 4 | `obu1` | Трек без місії → обрати розрахунок-кандидат → «Запропонувати місію» |
| 5 | `cmd02` | Санкціоновану місію свого розрахунку → «Прийняти»; `cmd03` — прийняту → «Пуск» з вибором перехоплювача |
| 6 | `cmd06` | Місію, що виконується → доповідь про результат (місія закривається, трек — «знищений») |
| 7 | `r09_1` | «Аналітика»: змінити період (з 01.06) — частка влучань, час реакції, результати розрахунків |
| 8 | `r08_1` | «Ресурси»: фільтри за позицією і станом, сторінки списку, додавання / зміна перехоплювача |
| 9 | `r07_1` | «Сенсори»: фільтри за типом і станом; зміна стану дозволена лише за діаграмою станів |
| 10 | `r11_1` | «Аудит»: перевірка ланцюжка хешів, фільтр за сутністю; «Користувачі» — фільтр за станом, блокування |
| 11 | будь-хто | П’ять неправильних паролів поспіль блокують обліковий запис (розблоковує `r11_1`) |

Кожна роль бачить лише свої розділи меню; спроба відкрити чужий розділ за адресою дає «Недостатньо прав».
